# 门打不开 / 关不上：处置脚本

## 用户报「取件时门打不开」（最常见）

1. 先用查单工具确认：订单在不在、进行中还是已结束、是不是本人订单。
2. 订单正常 → 用重开门工具**试一次**。
3. 成功 → 提醒用户"门已开，请取放物品后关好柜门"。
4. 失败（设备无回执/离线/拒绝）→ 不再试第二次，直接用建单工具转报
   `DEVICE_FAULT`，备注里写清：点位柜机格口（工具查到的）+ 用户描述 +
   已远程重开一次 + 结果。告知用户"已为你转报，会有工作人员联系你，
   请保持手机畅通；你的东西在柜内是安全的，柜门已锁好"。

## 用户报「存件时柜门没开/存不进去」

- 查单：订单不存在或已取消 → 说明当时下单未成功、费用没扣（预收未成功不产生账），
  让他重新走一遍存件流程。
- 订单存在且进行中 → 按上面的重开脚本处理（重开一次 → 失败转报 `DEVICE_FAULT`）。

## 用户报「门关不上」

- 这是设备侧问题，不尝试远程操作，直接转报 `DEVICE_FAULT`
  （备注写"用户报柜门无法关闭"，同样带点位信息）。
- 若用户自述"人已离开，不确定门关没关"，也转报，类型用 `DOOR_LEFT_OPEN`，
  让业务员电话核实。

## 用户报「取件码/开柜验证码不对」

- 这是取件码连错锁定：连续错几次后开柜会被暂时锁住（防试错）。
- 告知用户"先别再试了，等一会儿再取，或用订单页的结束/开柜入口重新验证"。
- 锁定期间你无法替他开柜（重开门也会被拒），不要反复尝试。
