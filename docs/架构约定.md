# 架构约定（底座阶段）

> 本文件是**约定的唯一来源**。后续任何分层、命名、错误码、配置方式的改变，先改这里再改代码。

## 1. 分层与命名

- 包根：`com.wherelee.cabinet`，Maven 坐标 `com.wherelee:cabinet-server`
- 单模块 + 分包（阶段 1 业务变厚后再评估拆多模块），包边界即依赖方向，**禁止反向依赖**：

```
interfaces      对外接口：admin（后台）/ mini（骑手端）/ system（自检），两端 Controller 不共用
application     用例编排、事务边界（@Transactional 只在这一层）
domain          实体、枚举、领域服务、仓储接口（不引用任何技术框架）
infrastructure  mapper、缓存、消息、外部 SDK、多租户等技术实现
common          与业务无关的通用能力：响应体、错误码、异常、链路、注解
config          Spring 装配（数据源、MyBatis-Plus、OpenAPI…）
```

- 接口路径按端划分：`/api/admin/**`、`/api/mini/**`、`/api/system/**`
- DTO 进出参不与 Entity 混用；Entity 不出 infrastructure 之外的返回值

## 2. 中间件与数据源职责

| 组件 | 用途 | 库/位置 | 备注 |
|---|---|---|---|
| MySQL 8.0.44 | **业务主库**（唯一被 MyBatis-Plus 接管） | `cabinet_dev` / 测试 `cabinet_test` | `@Primary` 数据源 |
| PostgreSQL 18.3 + pgvector 0.8.2 | agent / 向量检索 | `cabinet_agent` | 只走 `pgJdbcTemplate`，不进 ORM |
| Redis | 缓存 / 登录态 / 限流 | **db 8**，key 前缀 `cab:` | 本机为多项目共用实例，禁止用 db 0 |
| RocketMQ 5.3.1 | 业务异步事件 | namesrv `127.0.0.1:9876` | topic 前缀 `cabinet_`，消费组 `cabinet-*-consumer` |

- **双数据源的事务陷阱**（已踩坑位，勿回退）：Boot 的 `DataSourceTransactionManagerAutoConfiguration` 是
  `@ConditionalOnMissingBean(PlatformTransactionManager.class)`。一旦注册了 `pgTransactionManager`，
  自动配置就退让，`@Transactional` 会静默作用在 PG 上、主库回滚失效。
  因此 `MysqlDataSourceConfig` 显式声明 `transactionManager` 并标 `@Primary`；操作 PG 需事务时写
  `@Transactional("pgTransactionManager")`。
- MyBatis-Plus 3.5.9 起，分页/多租户/防全表更新这类依赖 JSqlParser 的拦截器在独立模块
  `mybatis-plus-jsqlparser`，漏引会在编译期报「找不到符号」。

## 3. 统一响应与错误码

- 一律返回 `R<T>`：`code` / `message` / `data` / `traceId` / `timestamp`；`data` 为 null 时不序列化
- 错误码分段：`0` 成功；`1xxxx` 业务；`4xxxx` 客户端（参数/认证/权限/限流）；`5xxxx` 服务端
- 业务异常（`BizException`）→ **HTTP 200 + 业务码**；客户端/服务端类异常 → **HTTP 状态码与语义一致**（400/401/403/404/405/429/500）
- 生产环境 `cabinet.exception.echo-detail=false`，外部只见 `系统繁忙`，内部堆栈只进日志

## 4. 链路追踪与日志

- `TraceIdFilter` 最高优先级执行：沿用合法的 `X-Trace-Id`（8–64 位 `[0-9A-Za-z_-]`，防日志注入），否则生成
- traceId 进 MDC → 日志 pattern `[trace:%X{traceId:-none}]`，并回写响应头；`R` 自动带出，前端报障可直接给 ID
- 日志目录 `logs/`（已 gitignore）：`cabinet-server.log` 按天+50MB 滚动、留 15 天封顶 1GB；`cabinet-server-error.log` 只收 ERROR，留 30 天
- **线程池/异步必须传递 MDC**，否则子线程日志丢 traceId（用到异步时统一走装饰过的 Executor，不裸用 `new Thread`）

## 5. 配置与密钥

- `application.yml` 公共项 + `application-{dev,prod}.yml` 差异项；prod 不给地址/账号默认值，缺失即启动失败（fail fast）
- 本地密钥来源 `server/.env`（properties 格式，经 `spring.config.import=optional:file:.env[.properties]` 注入），
  `.env` 已 gitignore，模板是 `.env.example`
- HikariCP 走 `@ConfigurationProperties` 直接绑定，属性名是 `jdbc-url` 而不是 `url`（写错会静默连不上）
- `springdoc.swagger-ui.groups-order` 在 2.8 是枚举 `asc/desc`，不是旧版 `alpha`（写错会让上下文启动失败）

## 6. 测试分层

- 单测（默认）：`mvn test`，surefire `excludedGroups=integration`，不依赖外部环境
- 集成测试：`mvn test -Pintegration`，`@Tag("integration")`，直连本机真实中间件
  （见 `MiddlewareConnectivityTest`）。**环境没准备好就该红**，不做 mock 掩盖
- 本机无 Docker → 用真实实例代替 Testcontainers；CI 里补 Testcontainers 版本（阶段 CI 时接）

## 7. 已记录的简化项（按红线要求显式登记，待办由用户拍板）

| 项 | 简化成什么 | 企业标准 | 影响 | 何时补 |
|---|---|---|---|---|
| RocketMQ 可靠性 | 仅接 producer 配置 + 集群健康检查，无消费者 | 死信队列 + 重试策略 + 消息幂等表 + 轨迹 | 无真实异步场景可验证 | 阶段 1 出现业务事件（订单状态、开锁结果）时 |
| 多租户 | 上下文与 `TenantLineInnerInterceptor` 未接 | 租户字段自动注入 + 越租防护 + 白名单表 | **表结构定下来后补最贵**，故列为下一刀第一优先 | 下一步（auth7） |
| 接口安全 | 无 `@Idempotent` / `@RateLimit` / `@OperationLog` | 注解 + AOP + Redis 实现 | 业务接口上线前必须有 | 下一步（auth7） |
| 集成测试环境 | 本机真库代替容器 | Testcontainers 隔离环境 | CI 与本地行为不一致（版本漂移） | CI 搭建时 |

## 8. 自检清单（改完代码本地跑一遍）

```powershell
cd server
mvn -B test                    # 单测
mvn -B test -Pintegration      # 集成（需 Redis / RocketMQ 已启动，见环境备忘）
mvn -B spring-boot:run         # 起服务
curl.exe -s http://127.0.0.1:8080/api/system/health   # 期望 overall UP，逐项 db/redis/rocketMQ UP
```
