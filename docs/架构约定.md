# 架构约定（底座阶段）

> 本文件是**约定的唯一来源**。后续任何分层、命名、错误码、配置方式的改变，先改这里再改代码。

## 1. 分层与命名

- 包根：`com.wherelee.cabinet`，Maven 坐标 `com.wherelee:cabinet-server`
- 单模块 + 分包（阶段 1 业务变厚后再评估拆多模块），包边界即依赖方向，**禁止反向依赖**：

```
interfaces      对外接口：admin（后台）/ mini（骑手端）/ system（自检），两端 Controller 不共用
application     用例编排、事务边界（@Transactional 只在这一层）
domain          实体、枚举、领域服务、仓储接口（不引用任何技术框架）
infrastructure  mapper、缓存、消息、外部 SDK、多租户等技术实现
common          与业务无关的通用能力：响应体、错误码、异常、链路、注解
config          Spring 装配（数据源、MyBatis-Plus、OpenAPI…）
```

- 接口路径按端划分：`/api/admin/**`、`/api/mini/**`、`/api/system/**`
- DTO 进出参不与 Entity 混用；Entity 不出 infrastructure 之外的返回值

## 2. 中间件与数据源职责

| 组件 | 用途 | 库/位置 | 备注 |
|---|---|---|---|
| MySQL 8.0.44 | **业务主库**（唯一被 MyBatis-Plus 接管） | `cabinet_dev` / 测试 `cabinet_test` | `@Primary` 数据源 |
| PostgreSQL 18.3 + pgvector 0.8.2 | agent / 向量检索 | `cabinet_agent` | 只走 `pgJdbcTemplate`，不进 ORM |
| Redis | 缓存 / 登录态 / 限流 | **db 8**，key 前缀 `cab:` | 本机为多项目共用实例，禁止用 db 0 |
| RocketMQ 5.3.1 | 业务异步事件 | namesrv `127.0.0.1:9876` | topic 前缀 `cabinet_`，消费组 `cabinet-*-consumer` |

- **双数据源的事务陷阱**（已踩坑位，勿回退）：Boot 的 `DataSourceTransactionManagerAutoConfiguration` 是
  `@ConditionalOnMissingBean(PlatformTransactionManager.class)`。一旦注册了 `pgTransactionManager`，
  自动配置就退让，`@Transactional` 会静默作用在 PG 上、主库回滚失效。
  因此 `MysqlDataSourceConfig` 显式声明 `transactionManager` 并标 `@Primary`；操作 PG 需事务时写
  `@Transactional("pgTransactionManager")`。
- MyBatis-Plus 3.5.9 起，分页/多租户/防全表更新这类依赖 JSqlParser 的拦截器在独立模块
  `mybatis-plus-jsqlparser`，漏引会在编译期报「找不到符号」。

## 3. 统一响应与错误码

- 一律返回 `R<T>`：`code` / `message` / `data` / `traceId` / `timestamp`；`data` 为 null 时不序列化
- 错误码分段：`0` 成功；`1xxxx` 业务；`4xxxx` 客户端（参数/认证/权限/限流）；`5xxxx` 服务端
- **HTTP 状态按错误码族给**（`GlobalExceptionHandler.httpStatusFor`）：`1xxxx` → 200（请求处理完了，只是结果不满足）；
  `401xx` → 401，`403xx` → 403，`404xx` → 404，`405xx` → 405，`409xx` → 409，`429xx` → 429，其他 `4xxxx` → 400；
  `5xxxx` → 500。前端据此区分“去登录”/“无权限”/“提示重试”，全返 200 就没法区分
- 生产环境 `cabinet.exception.echo-detail=false`，外部只见标准文案，内部堆栈只进日志

### 3.0 两个必须防住的异常处理陷阱（第三刀实测抓到）

- **`@PreAuthorize` 拒绝会被兜底 `Exception` 处理器抢走**，变成 500 + 50000：前端把权限不足当
  “系统异常、稍后重试”，用户重试还是不行；服务端告警也被弄成噪声。
  必须显式写 `@ExceptionHandler(AccessDeniedException.class)`。
- **MyBatis-Spring 会把异常转译成 `DataAccessException`**，埋在 cause 里的 `BizException`（如 40301）
  会被当成系统异常。处理方式：`@ExceptionHandler(DataAccessException.class)` 里沿 cause 链
  最多向下 10 层找 `BizException`，找到就按它的错误码响应，否则才归为系统异常。
- **全局异常处理器只能处理 Controller 内部抛出的异常**：过滤器（Security）里抛的它管不到，
  所以 401/403 的响应体要靠 Security 自己的 `authenticationEntryPoint` / `accessDeniedHandler`
  写（见 `AuthFailureWriter`），两处都要保持 `R` 结构一致。

## 3.1 实体基类与自动填充的坑（集成测试实测抓到）

- `@TableLogic` **只负责查询条件与删除语句，不会在插入时赋值**；想让 `deleted` 在插入后就是确定值，
  必须额外标 `@TableField(fill = FieldFill.INSERT)`。否则靠 DB 列默认值，插入能成功但内存里
  的实体 `deleted` 仍为 null，业务代码紧接着用这个实体就会拿空值。
- `strictInsertFill` / `strictUpdateFill` **只填当前为 null 的字段**。对 `updateTime` 而言这是错的：
  它在插入时已被填过，更新时会被跳过，导致 `update_time` 永远等于创建时间。
  所以 `updateFill` 里用 `setFieldValByName`（无条件刷新）。
- 显式赋值优先：`strictInsertFill` 的"只填 null"特性正好给补录/迁移留了口子（保留原始 create_time）。
- 存储精度：MySQL `DATETIME(3)` 对秒小数部分是**四舍五入**，Java `LocalDateTime` 带纳秒，
  读写一轮会有 ±1ms 漂移；时间列统一用 `DATETIME(3)`，断言用容差而不是等值。

### 3.2 写入侧的租户守卫不能指望插件（集成测试实测出的坑）

真实 SQL 证据：

```sql
INSERT INTO probe_audit (id, name, tenant_id, create_time, update_time, deleted) VALUES (?, ?, ?, ?, ?, ?)
==> Parameters: ..., null      -- tenant_id 为 null 也写进去了，不报错
```

- `tenantId` 标了 `fill = INSERT`，MP 会**无条件把这一列写进 INSERT 语句**；
  `TenantLineInnerInterceptor` 发现列已存在就认为"业务自己给了值"，**既不再注入也不再校验**。
- 后果：无租户上下文时插入不报错，静默写入 `tenant_id = null` 的黑洞数据
  ——不属于任何租户，所有租户都查不到，但占着表。
- 分工定下来：**写入侧（INSERT）的租户守卫在 `AuditMetaObjectHandler` 里做**
  （`BaseEntity` 子类无上下文即抛 `BizException(40301)`）；
  **读/改/删侧由 `TenantLineInnerInterceptor` 做**（它会给 where 拼上 `tenant_id = ?`，
  没有上下文则拒绝执行）。两边各自成立，缺一不可。
- 测试含义：这类漏洞单租户环境永远测不出来，必须**同时存在两个租户**才能断言隔离是否真生效。

## 3.3 分页与排序（第5刀）

- 入参统一 `PageQuery`（`pageNum` / `pageSize≤200` / `orderBy` / `asc`），出参统一 `PageResult`
  （`pageNum/pageSize/total/pages/records`），**不返回 hasNext 之类派生字段**
- 转换只走一处：`PageSupport.toPage(query, 白名单)`；`common` 不依赖 MyBatis-Plus，
  所以 ORM 换掉也不动接口契约（ArchUnit 有机检规则）
- `orderBy` 传**实体属性名**而不是列名：不暴露 schema，且白名单可按属性校验
- 排序要过两道关：形状检查（`^[a-z][a-zA-Z0-9]{0,63}$`）+ **每接口声明的白名单**。
  只做形状检查仍不够：合法列名一样能排出不该看的信息。`order by` 拼的是标识符，
  预编译语句帮不上忙，这是真正的注入口
- 报错不回显可用排序字段（否则等于送一份可猜字段的探测表）
- **接口不指定排序时必须兜底一个稳定排序**（默认 `id desc`）：MySQL 无序分页会让记录
  在翻页时被跳过或重复出现，这种 bug 在测试库里几乎看不出来
- 查询接口不加 `@OperationLog`：只读请求进审计会快速灌满表格，抬高噪声后真正该看的写操作没人看

## 3.4 安全默认拒绝（第5刀）

- 四条安全链：`@Order(1)` 公开（`/api/system`、`/api/public`、`/actuator/**`、文档、`/error`）
  → `(2)` admin → `(3)` mini → `(4)` **兜底 `/**` 一律要求已认证**
- 兜底链必需：多个 `securityMatcher` 只处理各自匹配的路径，没被任何链命中的请求会**绕过整套安全过滤**。
  新加一个接口、写错一个路径前缀，就是个无鉴权入口；默认拒绝把“静默暴露”变成“401，立即看得见”

## 4. 链路追踪与日志

- `TraceIdFilter` 最高优先级执行：沿用合法的 `X-Trace-Id`（8–64 位 `[0-9A-Za-z_-]`，防日志注入），否则生成
- traceId 进 MDC → 日志 pattern `[trace:%X{traceId:-none}]`，并回写响应头；`R` 自动带出，前端报障可直接给 ID
- 日志目录 `logs/`（已 gitignore）：`cabinet-server.log` 按天+50MB 滚动、留 15 天封顶 1GB；`cabinet-server-error.log` 只收 ERROR，留 30 天
- **线程池/异步必须传递 MDC**，否则子线程日志丢 traceId（用到异步时统一走装饰过的 Executor，不裸用 `new Thread`）
- **耗时不做成响应头**（实测坑）：Spring 写回 body 时会 flush，响应在控制器返回时就已 committed，
  filter 在 `finally` 里 `setHeader` 会被容器**静默丢弃**；而 MockMvc 的 mock response 不真提交，
  所以断言会假绿。耗时只看服务端日志（`AccessLogFilter`，慢请求升 warn）与 Nginx `$request_time`，
  聚合统计用 actuator 自带的 `http.server.requests` 指标
- 写响应头必须在响应体之前：任何“后置往响应里补东西”的设计（包 header、包状态码）都要先问一句
  “此时响应 committed 了吗”

## 4.1 JVM 参数与指标暴露（第5刀）

- **JVM 参数单一来源 `deploy/jvm.opts`**：本地 `scripts/run-app.ps1` 与第8刀的 systemd 单元都读它，
  不存在“本地一套参数、线上另一套”。含 `-Xms/-Xmx`、Metaspace 上限、OOM 时 heap dump + 快速退出、
  GC 日志滚动输出
- 它**不叫 `*.env`**：本仓库里 `.env` 的含义是“密钥、绝不入库”，已提交的参数文件不能占同一个
  名字空间，否则“密钥只进 .env”这条例和推前必查的扫描模式都会被混淆
- 指标**只埋不采**：dev 额外暴露 `metrics` 与 `prometheus`（实测 `curl /actuator/prometheus` = 200，
  `jvm_memory_used_bytes` 可取）；prod 的 `exposure.include` 只留 `health,info`
- 靠 exposure 而不是靠安全规则：**未暴露的端点根本不存在**（`heapdump`/`env` 这类经典泄露点直接消失），
  安全规则会漏，白名单不会
- MockMvc 验不了 `/actuator/prometheus`（靠内容协商输出文本格式，无 Accept 头时 404），
  指标存在性改用 `/actuator/metrics` 断言；文本端点由真实 curl 验证

## 4.2 切面顺序与故障策略（第四刀）

执行顺序由外到内（`@Order` 已固定，**不要改数值**）：

```
TraceIdFilter(HIGHEST+10) → AccessLogFilter(HIGHEST+20) → Security 过滤器链
  → @OperationLog(-200)      审计：最外层，连被鉴权拒绝的尝试也要留痕
  → @RateLimit(-150)          限流：先挡量，不消耗下游资源
  → @Idempotent(-100)         幂等：只对真正要执行的请求占位
  → @PreAuthorize             Spring Security 方法级鉴权
  → @Transactional            事务边界（只在 application 层）
  → 业务方法
```

为什么负值：Spring Security 的方法级拦截器默认落在正数区间，我们的切面取负才能包在它外面；
否则“权限不足被拒”这种恰恰最该记审计的调用根本进不到切面里。

| 切面 | Redis/DB 不可用时 | 为什么 |
|---|---|---|
| `@RateLimit` | **fail-open**（放行 + error 日志） | 限流是保护措施不是访问控制；它故障时把整站变成 500 是更大的事故 |
| `@Idempotent` | **fail-closed**（拒执行，报 50100） | 幂等是正确性约束，无法判断是否重复时放行会重复下单/重复开锁 |
| `@OperationLog` | 不向上抛，只记 error | 审计写失败不该打挂用户请求；代价是**审计不保证强一致**，不得用作计费/对账依据 |

脱敏两条路都要有：出参用 `@JsonMask`（标在 VO 字段上），日志/审计入参用 `MaskUtils`
（按**字段名**识别，含嵌套与数组，命不中则全遮兼容脏数据）；只做其中一条等于另一半仍为明文。

## 5. 配置与密钥

- `application.yml` 公共项 + `application-{dev,prod}.yml` 差异项；prod 不给地址/账号默认值，缺失即启动失败（fail fast）
- 本地密钥来源 `server/.env`（properties 格式，经 `spring.config.import=optional:file:.env[.properties]` 注入），
  `.env` 已 gitignore，模板是 `.env.example`
- `.env` 是 **properties 格式**（Spring 按 ISO-8859-1 读），所以**值里不要写中文**，注释也别用全角标点开头；
  需要中文说明请写到 `.env.example` 以外的文档里
- HikariCP 走 `@ConfigurationProperties` 直接绑定，属性名是 `jdbc-url` 而不是 `url`（写错会静默连不上）
- `springdoc.swagger-ui.groups-order` 在 2.8 是枚举 `asc/desc`，不是旧版 `alpha`（写错会让上下文启动失败）
- **本地端口分配**：后端 `8080`、admin 前端 `8082`（5173 作为兼容项也在 CORS 白名单里）。
  **8081 已被本机 RocketMQ 5 的 proxy 组件占用**（监听 `::8081`），vite 抢它时报的是
  `EACCES: permission denied` 而不是 `EADDRINUSE`，很容易误判成权限问题——
  先查 `Get-NetTCPConnection -State Listen -LocalPort 8081` 的拥有者再改配置
- **JSON 里的数字与字符串**：ID 字段声明为包装类型 `Long`（全局序列化成字符串，防 JS 精度丢失），
  计数与时长声明为原始 `long`（保持 JSON 数字）。**不得给 `Long.TYPE` 也挂上 ToString 序列化**，
  否则分页的 `total` 会变成 `"1"`，而前端类型写的是 number
- 上面这条是真实 HTTP 测出来的：`jsonPath(...).value(1)` 对 number 与 string 是**宽容比较**，
  MockMvc 下永远绿。涉及类型契约的断言必须用 `isNumber()` / `isString()`，不能用 `value(...)`

## 6. 测试分层

- 单测（默认）：`mvn test`，surefire `excludedGroups=integration`，不依赖外部环境
- 集成测试：`mvn test -Pintegration`，`@Tag("integration")`，直连本机真实中间件
  （见 `MiddlewareConnectivityTest`）。**环境没准备好就该红**，不做 mock 掩盖
- 本机无 Docker → 用真实实例代替 Testcontainers；CI 里补 Testcontainers 版本（阶段 CI 时接）

## 6.1 前端（admin）门禁（第6刀）

- 三道门禁都要为零告警：`npm run lint`（`--max-warnings 0`）、`npm run typecheck`（vue-tsc）、`npm run build`
- **`src/components.d.ts` 与 `src/auto-imports.d.ts` 必须入库**：它们由插件生成，
  而 typecheck 在首次构建前就要看到它们；不入库则新 clone 必红
- 按需引入的两个坑：直接 `import` 的 API（`ElMessage`）与指令（`v-loading`）**不走组件解析器**，
  样式/注册必须手工补，否则是"不报错但没样式/不生效"这种静默失效
- `no-undef` 在 ESLint 里关掉：这事情 TypeScript 已经做了，留着只会对 `window`/`localStorage` 误报
- 验证顺位：先看真实 HTTP（curl 走前端的请求序列），再看界面。只验 build 不算联调

| 接口安全 | 无 | `@Idempotent` / `@RateLimit` / `@OperationLog` + AOP 已接（第四刀） | 幂等未写业务键时退化为用户+URI+入参哈希 | 下单/开锁/退款类接口必须显式 `key` 且 `requireKey=true` |
| 集成测试环境 | 本机真库代替容器 | Testcontainers 隔离环境 | CI 与本地行为不一致（版本漂移） | CI 搭建时 |
| 前端 token 存放 | access/refresh 均存 localStorage | refresh 放 httpOnly + SameSite Cookie，access 只存内存 | XSS 一旦发生，两个 token 都能被读走 | **接真实用户数据前必须换** |
| 前端测试 | 只有 lint + 类型 + 构建门禁 | 组件/交互测试（Vitest + Playwright）与后端契约测试 | 登录、权限菜单、分页这些流程目测不测，改动可能默默坏 | 阶段 1 有真实业务页时 |

## 8. CI

- 工件：`.github/workflows/ci.yml`，**4 个 job**：
  - `unit-tests`：`mvn -B test`（无中间件依赖，先绿）
  - `frontend-admin`：`npm ci` + lint + typecheck + build（在 `admin/` 工作目录）
  - `secret-scan`：① `git ls-files` 中不得出现 `.env`/`logs/`/`*.log`/`target/`/`node_modules/`/`*.pem`/`unpackage/`；② `git grep` 只扫确定性密钥格式（私钥块、`ghp_`、`github_pat_`、`AKIA`、`LTAI`、`xox*`），故意不扫 `password=` 这种文本，避免把 `${MYSQL_PASSWORD}` 占位符误判
  - `integration-tests`：`needs: unit-tests`，MySQL/pgvector/Redis 用 `services`，RocketMQ 用 step 起容器
- **本地与 CI 跑同一批 `@Tag(integration)` 用例**，区别只在环境供给：本地真实例，CI 服务容器；测试代码不分叉
- RocketMQ 不进 `services` 的两个原因：broker 必须 `brokerIP1=127.0.0.1`（否则向 namesrv 注册的是容器内网 IP，runner 宿主进程连不上），且需要 `--net host` 与显式堆参数（镜像默认 8G 堆会弄挂 7G 内存的 hosted runner）
- 配置版本差异（已登记的简化）：CI 用 `pgvector/pgvector:pg16` + `redis:7`，本地是 PG 18.3 + Windows Redis 5.0.14；MySQL 两边均 8.0。差异只影响集成测试环境，版本漂移风险待 CI 跑稳后统一
