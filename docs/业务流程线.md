# 业务流程线（用户线 / 运维现场线 / 客服与资金线）

这份文档只做一件事：**把三条线画到分叉上，并标明每一个分叉今天走到哪儿**。
不是理想流程图——理想图谁都会画，能用的是"这条分支现在有没有代码接住"。

每个节点后面带一个状态标记：

| 标记 | 含义 |
|---|---|
| ✅ | 后端已实现且有用例覆盖 |
| 🟡 | 后端已实现，**但 mini/admin 还没有入口**（等于用户或运营走不到） |
| ⬜ | 未实现（规则已定，代码没有） |
| ❓ | **规则本身没定**，需要用户拍板；我不自行补 |
| ⛔ | 现实中会发生，目前系统没有任何接住动作（最危险的一类） |

规模前提：60 点位 / 180 柜机 / 约 4320 格口，全城分布，**运维不可能被一次异常叫到现场**
（这条前提决定了下面很多分支为什么走"计费惩罚 + 台账排队"而不是"派人"）。

## 1. 用户线

### 1.1 到柜前（还没下单）

```
打开 mini → 登录（微信 code；dev 下 mock）
   ├─ 账户被禁用 ❓  今天表现：登录即 403（权限装载空集合），但**页面没有一句"你被禁用了、原因、怎么申诉"**
   ├─ 有欠费 ⬜      首页应显示"欠 N 点，补缴后可继续下单"；现只有下单时抛错
   └─ 有逾期未取的单 ⬜ 首页应置顶提示（没有推送渠道，可见就是唯一的提醒）
→ 选点位 → 选柜机 → 选尺寸
```

需要你在界面上看到但今天看不到的：**逾期、欠费、押金未退、门未关、"你的格口曾被他人开启/发现遗留物"**。
这几条都属于 🟡/⬜，归第 15 刀。

### 1.2 分配格口（钱与位的起点）

```
提交下单（requestId 幂等）
   ├─ 欠费 > 0 ✅ 直接拒（无阈值，还清自动恢复）——不靠前端置灰
   ├─ 柜机离线 ✅ 拒绝新分配（S-09：不可存、可取）
   │     └─ ⛔ 用户站在离线柜机前，系统没有任何"去旁边哪台还有位"的引导
   ├─ 该尺寸无空位 ✅ 返回无位
   │     └─ ❓ 是否允许"加价升一级/降级用别的尺寸"，以及放不进去要换格口的改配与差价规则：全无
   ├─ 并发争抢 ✅ 四策略（悲观锁/条件 CAS/Redis+Lua 预扣/Redisson），不变量"超卖=0"有用例
   ├─ 余额不足冻结不了押金+预估 ✅ 拒单，说清要多少
   └─ 分配到的格口硬件连续失败 ✅ 达阈值摘出可售池 + 重分配
```

**下单成功即冻结押金 + 预估费用，价格抄进快照**（此后改价/回滚都追不到这张单）✅。

### 1.3 开门投件（容错期）

```
下发 OPEN → 柜机开门
   ├─ 无回执 ✅ 超时标"待确认"，幂等重试；仍失败则回退且不动资金（指令不回执行结果，靠回扫）
   ├─ 执行失败（打不开）✅ 判据是"正在执行的动作"而不是当前状态：OPEN 失败→留在 RESERVED 可重试
   └─ 门开了
        ├─ 5 分钟内关好 ✅ 关门起计（免费窗口内不计费）
        ├─ 5 分钟到了还没关 ✅ **从到期时刻起计**，格口标 DOOR_OPEN
        │     └─ 用户这时点"关门"会怎样？✅ 关门校验按门态准入（不看订单状态），照常闭合
        ├─ 谎报关门（说关了其实没关）✅ 门磁二次校验 → 标 SENSOR_CONFLICT，**计费继续**
        └─ ⛔ 投完件人走了、门一直开着：计费到封顶（单日 12 小时价、总额 3 天）
              → 停止续排 + log.error + 计数
              → **没有任何人/动作接手**（工单暂缓；提醒无渠道）
              → ❓ 封顶后长期无人取件（例如 30 天）物品能不能处置、几次联系不上算放弃：无规则
```

**放不进怎么办** ❓：用户把门开着、件拿在手里发现塞不进去——今天能做的只有"临时开柜"或"取消"。
"取消"在开过门后有凭据要求（见 1.5），**换格口没有流程**。

### 1.4 使用中

```
临时开柜 OPEN_TEMP ✅（单未结束用它，这就是"再开一次门"的唯一出口，REOPEN 已删）
   └─ 临时开柜后不关门 ✅ 容错起点不刷新（不变量 I10：started_at 落定不再改），不会因为再开一次门把计费往后推
续期 ❌ **后端没有这个接口**（规划 §5.8 把"续期、沿用原快照价"当既有能力写着 → 已在本文件 §5 记为缺口）
逾期 ✅ 单推到 EXPIRED，计费封顶，**仍可取件**（欠的是债，不是留置权）
```

### 1.5 结束取件（整个业务最硬的一屏）

规则：**选结束 + 门关 + 柜内无物**，三者齐了才停计费。现场与远程同一套标准。

```
点"结束"
   ├─ 门没关 ✅ 拒（现场与远程都拒），提示先关门
   ├─ 门关 + 物检说空 ✅ 结算 → 押金异步退还 → 格口回可售
   ├─ 门关 + 红外说**有物** ✅ 拦住，只给两条正路：
   │     ├─ 取走（→ 回 1.4 临时开柜，取完再关再结）
   │     ├─ **声明放弃** ✅ → 结束 + 格口转 CONTENT_LEFT（等运维清柜）
   │     └─ **否认（我说没有）** ✅ → 进争议阶梯：
   │           ├─ L2 AI 看图复审 🟡 端口与实现都在（MiMo 已实测接通），
   │           │      但**没有照片**（不存图、没有基准照采集动作）→ 实际只能答"无法判断"
   │           │      └─ ⇒ 今天所有否认都**直接落到 L4 人工**，客服/运营量按最坏情况估
   │           ├─ AI 判无（有图之后）✅ 视为误报：允许结束，**计费终点回退到争议起点**（只免争议那一段）
   │           ├─ AI 判有 ✅ 继续拦，回到"取走/放弃"
   │           └─ 复审次数用尽（默认 2 次）✅ 一次模型调用都不再发，直接转人工
   ├─ 门关但**测不到**（物检坏了/离线/结论超龄）✅ 不对称处置：
   │     ├─ 现场 → **不拦人**，允许走，但格口一律标 CONTENT_UNVERIFIED（锁住等一次人来确认）
   │     └─ 远程 → 直接拒（远程结束不豁免任何条件）
   ├─ 远程结束（人在别处点结束）✅ 三条件同标准 + **另收该格口 2 小时单价**（进快照、单独一条流水）
   └─ 结算扣不到钱 ✅ 只记欠费、**绝不锁件**（东西在用户手里是本域最重要的事）；下次下单被 1.2 挡住

取消（还没投件就反悔）
   ├─ 没开过门 ✅ 解冻、退押金、格口回可售
   └─ 开过门 ✅ 有物直接拒；无凭据不拦人但锁格 CONTENT_UNVERIFIED（取消不比结束更松）
```

### 1.6 取件之后的事后线

```
打开订单详情 ✅ 看到实际计费分钟数、点数流水、押金状态
发现自己格口里有别人的东西 ✅ report-leftover → 上报者**免单退回**、格口锁 CONTENT_LEFT、原单打标
   └─ 🟡 原单用户侧"你的格口曾被他人开启/发现遗留物"的可见提示：接口有数据，界面没有（第 15 刀）
取件码输错太多次 ✅ 锁该单开柜能力
   └─ 备用路径 ✅ 客服核验 → 后台强制开柜（二次确认 + 事由 + 审计）
   └─ ❓ **主路径凭什么放人没定**：只凭取件码？取件码可被拍照、转发、截图
```

## 2. 运维现场线

这条线的现实约束：**全城多点分布，一次出勤的成本高于一个格口被占的损耗**。
所以设计上不让任何异常直接触发派工，而是**排队 + 按片区顺路清**。这也意味着：
"什么时候有人来"取决于排班，而**排班与片区在系统里还没有表达**（见 §4）。

```
触发源
   ├─ 后台异常台账（按原因码 + 停留时长排序，卡最久的在前）✅ 已实现
   ├─ "待确认清空 / 长期未关门"清单 🟡 数据能查，admin 只有台账页有它
   ├─ 争议 L4 转人工 🟡 机制到 log + 指标为止，**没有人被指派**
   ├─ 用户上报遗留物 ✅ 台账里出现 CONTENT_LEFT
   └─ 硬件故障停用/恢复 ✅ 连续失败摘出可售池，状态位 FAULT

到场之后（一个格口的标准处置序列）
   1. 看清是哪一类（四类各要求不同动作）✅ 台账详情带**观测时间线**（谁说过有、AI 说过没有、置信度多少）
   2. 需要开箱 → 强制开柜 ✅ 二次确认 + 事由 + 指令留痕；**不降级更强的锁**（遗留物不会因开一次门消失）
   3. 看柜内：
      ├─ 是空的 → 清柜 ✅ 标正常 + 说明必填 + 写 RECOVER 流水（门没关时拒绝，防"关着却永远异常"）
      │        └─ 若这是争议误报 → 免除争议期间费用 ✅ 服务与权限点都在（`locker:order:waive-fee`）
      │           ⚠️ 但**没有 admin 界面**（🟡），而且这条链现在实际不会发生（没照片 → AI 不判无）
      ├─ 有物品 → ❓ **取出后放哪、登记什么、保管多久、失主怎么领回、能不能折价抵欠费**
      │            —— 全条线都没有规则也没有表结构，这是储物柜投诉的真实产地
      └─ 门/锁坏了 → 标 FAULT ✅；❓ 存量活动单的件怎么取回，没有流程（见 §3 汇合点 C1）
   4. ⛔ **发现门开着、里面没人**：系统里没有任何"关门"动作。
        清柜要求门已关、强制开柜只会让门更开 ⇒ 忘关的格口只能等它自己被子某次上报闭合
   5. 回填：处置人 + 时刻 + 依据 ✅（流水与审计有）
      ❓ **但"指派给谁、什么时候必须办完、没人办怎么办"没有任何表达**（工单暂缓的直接后果）
```

一条必须说的判断：**运维线目前"能动手，不能派工"**。所有处置都要求有人主动打开后台并认领，
这在运维只有 1~2 人时成立，规模化就会失效。轻量补法（不建工单表）：台账上两个动作
"指派给某运维 / 标记已处理"，字段落在现有故障流水里——这个我随时可以做，等你一句话。

## 3. 客服与资金线

```
入口
   ├─ 争议升级到人工（L4）🟡 只到日志/指标，无人认领
   ├─ 呆滞单（封顶后停止续排）⛔ 只 log.error + 计数
   ├─ 欠费追缴 🟡 拦截已做（挡新单、还清自愈），规划里的"催收任务"⬜ 未做
   │      └─ ❓ 催收做到什么程度：站内可见就够，还是要短信？（本项目无推送资质与公网域名）
   ├─ 押金悬挂（订单已终态而未退）✅ 清单可查（admin 资金待办页）+ 自动重试 ✅
   │      └─ ⬜ "手动重发退还"的动作没做（清单能看不能办）
   └─ 对账漂移（余额 vs 流水求和）✅ 作业能发现并报告
          └─ ⬜ 规划 §6 写的"修复提案 + 人工确认才执行"没做 → 后台**没有任何修数据的入口**

客服可执行的三个动作，**必须分权限点**（谁都不该一个账号全能）
   ├─ 禁用 / 启用客户 ✅ `locker:customer:disable`（事由必填、登录与下单双侧拦、只能人工解除）
   │      └─ ❓ 判定依据：欠多少算恶意？拒付几次？恶意上报几次？现在纯人工凭手感
   ├─ 免除争议费用 ✅ `locker:order:waive-fee`（四道前置：独立权限 / 两条互相打脸的证据 / 未终态 / 审计）
   │      └─ 金额不可填，由 `started_at → dispute_started_at` 算，所以**没有也不需要额度参数**
   └─ 清除格口异常 ✅ `locker:compartment:resolve`（门已关 + 说明必填）

❓ 需要定的一条：判定人与执行人要不要分开
   （例如"客服判定误报"和"执行免除"是不是必须换一个人）。
   现在靠三个独立权限点可以做到分开，但**没有任何规则要求必须分开**，一个超管账号可以自判自免。
   这是治理选择，不是技术选择，我不替你定。

汇合点（三条线交叉、目前没设计过的地方）
   C1 硬件故障柜里还有 N 张活动单：件怎么取回、谁通知、去不了现场怎么办 —— 无流程
   C2 离线柜机里的单：规则"仍可取件"✅，但门开不了 ⛔（现实与规则的缝）
   C3 呆滞单对应格口被长期占用：可售数下降是可接受代价，但"东西什么时候能处置"❓
   C4 一个账号同时占多格（家庭/团队共用）：技术允许，业务没定要不要限
   C5 价格形态：计价策略只有单价+封顶，没有分时段/节假日/长时折扣（规则没定所以没做，我不加）
```

## 5. 我在这张图上发现的、以前没记过的错

**续期被当成既有能力写了很久**：规划 §5 第 8 条写"续期：再冻结一次，沿用原策略快照"，
§5 用户流程与本次讨论里我都默认它有。刚才 grep mini 控制器才确认：**后端没有 renew 端点**。
它既没在第 12 刀做过，也没在"没做完清单"里被记过——这是漏记，不是简化。已列 F-05 并补进第 15 刀。

同一类风险我在这份文档里的处理办法：每个节点都带状态标记，🟡/⬜ 一律写出来而不是省略，
"现实会发生但系统没接住"的用 ⛔ 单标——因为那类问题最容易在流程图上被画成一条直线。
